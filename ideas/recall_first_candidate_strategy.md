# 高召回候选集策略总结

## 背景
当前 `exp18` 的结果已经说明，主要瓶颈不在于下游的打分感知机是否再加深，而在于上游候选框是否足够全。若候选本身漏掉真目标，后面的 MLP、reranker 或阈值搜索都很难把结果补回来。

## 核心思路
先把 proposal 做到“宁可多，不要少”，把召回尽量抬高，再在后面用更强的筛选器做精炼。

### 1. GroundingDINO 多阈值并集
对同一张图使用多个 box/text 阈值分别跑推理，例如：
- 0.02
- 0.04
- 0.06
- 0.08
- 0.10

把多次推理得到的候选框合并起来，而不是只保留单一阈值下的输出。这样做的目标不是减少误报，而是尽量把漏掉的真目标捞回来。

### 2. 每张图保留更多 top-K 候选
不要过早把候选压得太少。可以先保留每张图更多框，例如 top 50 / top 100，再统一做 NMS 去重。

这样做的原因是：
- 高阈值会让一些真目标直接消失
- 先保留更多框，再统一清洗，通常比前面卡得太死更稳

### 3. 先 class-agnostic 提召回，再做 class-aware 过滤
召回优先阶段可以先弱化类别限制，只保留“像目标”的框；随后再用类别信息、reranker 或分类头做筛选。

适用原因：
- 先减少漏检
- 再处理类别混淆和重复框
- 对小目标、遮挡目标更友好

### 4. 多 proposer 合并
不要只依赖一个候选生成器。可以把多个来源的候选合并：
- 不同阈值的 GroundingDINO
- 不同 prompt 下的 GroundingDINO
- 其他检测器/提议器的候选框

候选集越丰富，下游 reranker 的选择空间越大。

## 为什么比加深 MLP 更优先
当前问题更像是“上游候选不足”，不是“下游分类器太弱”。如果真目标没有进入候选集，MLP 再深也只能在错误集合里做选择，收益有限。

所以更合理的顺序是：
1. 先补召回
2. 再做去重和过滤
3. 最后再考虑加深打分器或引入更强的 set-level 模型

## 建议的实验顺序
1. 基线：当前 `exp18`
2. 召回增强版：多阈值并集 + 更高 top-K + 统一 NMS
3. 召回增强 + set-level reranker
4. 再做更深的 MLP / 注意力结构对比

## 预期收益
如果当前性能受候选覆盖率限制，那么这条路线通常比单纯加深感知机更有可能带来明显提升，尤其对 `Acc@0.5` 和 `mAP@0.5` 更关键。
